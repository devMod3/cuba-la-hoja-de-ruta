ZENBLOG FORENSIC MEMORY — DO NOT START FROM ZERO
==================================================
Product: La hoja de ruta
Engine: ZenBlog
Public site: https://cubalahojaderuta.blogspot.com/
Repository: devMod3/cuba-la-hoja-de-ruta
Active hardening line: lab-v0.9-production-hardening

WHY THIS FILE EXISTS
--------------------
This is a portable handoff for a human engineer or AI. Read it before changing code. The project must evolve by preserving contracts and working behavior, not by rediscovering requirements from scratch.

NON-NEGOTIABLE CHANGE RULE
--------------------------
If something works, freeze it unless it is explicitly inside the approved scope.
Workflow: audit → isolate owner → state protected surfaces → implement minimum coherent change → regression tests → CI → real Blogger QA → freeze after acceptance.
Always keep the last validated XML and SHA as rollback.

PRODUCT IDENTITY
----------------
Official site title: La hoja de ruta.
Home identity question: ¿Qué nos define?
Statement: Seguir el origen, los límites y el ejercicio del poder.
Supporting text: Conceptos, normas, documentos y análisis organizados para situar, relacionar y verificar cada afirmación.
Conceptual line: Soberanía · Constitución · Estado.

UX CONTRACT
-----------
Institutional/editorial/dark/sober. iOS-like means hierarchy, restraint, progressive disclosure, predictable interaction and strong touch ergonomics — not decorative imitation.
Empty space is structure.
Square geometry is preferred for institutional UI; profile portrait is intentionally circular.
Vertical page scroll belongs to reading, not interface. Article is the long-form reading exception. Explore owns a bounded internal results scroll.
Mobile must retain every essential function. Gestures enhance visible navigation; they never replace it.

PROTECTED BLOGGER ANATOMY
-------------------------
Exactly one #page_body.
Exactly one Blog1, under #page_body.
Never introduce zen_main as a replacement root.
Blogger remains CMS/public document host.
The repository theme is a composition shell around Blogger, not a replacement for Blogger internals.

PLAYER
------
Independent repository: devMod3/zen-radio-player.
Protected ZenBlog loader: v1.0.3.
ZenBlog must not close/hide/restyle player internals. It may reserve layout space through --zen-player-safe.

ARCHITECTURE
------------
Infrastructure (Blogger/storage) → adapters/contracts → domain/services → features → composition root → UI.

Public composition:

Public features:

- ArticleFeature

Adapters:

  - Admin only on /admin or /p/admin.html
  - About only when About is used
  - Inspector only when enabled or requested
This boundary exists to keep authoring/debug code off the reader critical path.

ROUTES
------
#zen-home
#zen-explore
#zen-about
#zen-radio-player is the independent player target.
Articles keep real Blogger URLs. Direct article → Portada must return to the homepage document.

MOBILE GESTURES
---------------
Enabled only on coarse-pointer devices <=900px.
Route sequence: Portada ↔ Explorar ↔ Acerca de.
Do not start a swipe on links, buttons, form controls, contenteditable, #zen-radio-player, #zen-article, .zen-results-scroll or data-zen-no-swipe.
Reserve 24px on left/right screen edges for OS/browser gestures.
Require horizontal displacement >=72px and horizontal dominance over vertical motion.

HOME
----
Discovery surface. Statement + highlighted/latest reading. Home may display title + summary. The highlighted card is the visual reference for the public social-sharing image.

EXPLORE — SEMANTICS FROZEN
--------------------------
Simple search = title-only.
Advanced mode uses structured metadata/services.
Rows = Type · Date · Title; no summaries.
Documentary year ≠ Blogger publication date.
No fake popularity sort.
Layout/responsive hardening must not alter query semantics.

ARTICLE
-------
Long-form reading surface. Preserve real Blogger content and URLs. Reading typography/width is deliberate. TOC rail becomes overlay at smaller widths. Print removes UI chrome. Article is intentionally excluded from global swipe navigation.

ABOUT / SITE PROFILE
--------------------
Data contract: zenSiteProfile.v1.
Contains profile, social links and related resources.
Only populated public fields render.
Portrait is circular.
The old public expanded Blogger details accordion and decorative arrows were removed for a quieter UI.

IMPORTANT: zenSiteProfile.v1 is currently browser-local. A photo stored there is NOT a global crawler-visible favicon. Admin exports the same photo as a 96×96 PNG. Public authoritative favicon must be uploaded in Blogger → Settings/Configuración → Favicon. A repository fallback favicon exists for initial public identity.

SOCIAL / X CARD
---------------
Social metadata is server-rendered in blogger/theme.xml. Never move it to runtime JavaScript.
Open Graph + X summary_large_image use assets/social/zenblog-social-card.png.
Card title comes from the current Blogger page title. Description uses Blogger metaDescription when available, otherwise the site mission fallback.
The image visually mirrors the Home highlighted-reading language.

SEO
---
Keep Blogger all-head-content: Blogger owns platform data, canonical integration and index/noindex authority.
ZenBlog adds product-level metadata: OG/X, homepage identity, preview/snippet policy and WebSite JSON-LD.
ZenBlog MUST NOT force index if Blogger account settings say noindex.
Do not invent Article structured-data values. Every structured property must be traceable to real server-visible content.

PUBLIC VISIBILITY
-----------------
Public HTTP access and search indexing are different states. The blog can load worldwide while not yet appearing in search results.
Account checks after deployment:
- Blogger → Settings → Privacy → Visible to search engines ON.
- Search description enabled/configured.
- Favicon uploaded from Admin export.
- Search Console property verified; inspect/request indexing when appropriate.
Do not claim indexing without evidence.

PERFORMANCE MODEL
-----------------
Production theme does NOT load dist/zenblog.css because that compatibility entry uses CSS @import.
Active theme links product CSS in parallel:
- tokens.css
- shell.css
- home.css
- explore.css
- article.css
- responsive.css

Initial public script budget:
1. dist/zenblog.js
2. tools/runtime/bootstrap.js
3. independent player

About/Admin/Inspector are lazy. Gesture module is lazy on touch-mobile. Fonts use preconnect + display=swap. Entry + composition root are modulepreloaded.
Do not add global critical-path dependencies without a documented reason.

RESPONSIVE
----------
Global tokens:
--zen-header-h
--zen-player-safe
--zen-safe-inline
--zen-reading-width

Test desktop, tablet, mobile, very narrow mobile, landscape/short-height, safe-area devices, long URLs, images/video/iframe, tables, pre/code. Major touch targets >=44px. Never scatter new hardcoded header heights when a token exists.

ADMIN
-----
Unified AdminShell tabs:
Metadata | Search Lab | Acerca de | Inspector
Old floating Metadata launcher must be removed after compatibility boot.

Metadata Manager v0.5 core is protected; Adaptive UI v0.6 decorates it rather than rewriting it.
Metadata registry key: zenMetadataRegistry.v2.

About Manager edits zenSiteProfile.v1 and handles photo upload + favicon export.

INSPECTOR
---------
Key: zenInspector.enabled.
Every exact DOM element is inspectable. Known logical owner remains visible in diagnostics.
Click opens modal; focus/select begins on component/node name.
Arrow cursor, not crosshair.
While ON, link href values are temporarily neutralized to suppress browser hover URL preview; they are restored exactly when OFF.
Alt+I loads/toggles Inspector.
When OFF it must not change reader behavior.

SEARCH LAB
----------
Diagnostic/admin only. It does not write metadata.
Rule: Metadata clasifica. Search Lab verifica.
Do not conflate Search Lab with public Explore.

STORAGE BOUNDARIES
------------------
zenMetadataRegistry.v2 — local documentary metadata (LAB)
zenSiteProfile.v1 — local profile/social/resources (LAB)
zenInspector.enabled — local Inspector state

These are infrastructure implementations, not the long-term architecture. Future shared persistence/auth must be introduced behind adapters/repositories so UI/features survive the migration.

DEPLOYMENT
----------
GitHub Pages deploys repository assets from main.
Blogger theme deployment is separate. Updating blogger/theme.xml in GitHub does NOT change the live blog.
A release therefore needs:
- exact validated SHA;
- full XML pinned to that SHA for LAB;
- install in Blogger;
- real Blogger QA;
- acceptance/freeze;
- merge/deploy stable main when approved.

COMMENTS POLICY
---------------
Comments are a virtue when they preserve WHY: Blogger workaround, compatibility node, invariant, performance boundary, security risk, deliberate no-change. Do not remove useful forensic comments during cleanup. Avoid comments that merely narrate syntax.

KNOWN DEBT / FUTURE PATH
------------------------
- Metadata and site profile still browser-local.
- Admin authentication is future work.
- Social image is a branded common fallback, not per-article generated media.
- Theme installation is still manual.
- Native ESM is intentional. A build/bundle pipeline may come later when it clearly lowers operational cost.
- Blogger may eventually be replaced or reduced to one ContentSource among several. Migrate behind contracts; do not rewrite working UX.
